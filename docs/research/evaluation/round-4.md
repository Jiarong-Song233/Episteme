# 第四轮评测：合并 #52–#65 之后的回归检查

日期：2026-11-16。

## 目的

第三轮之后，`main` 合并了 #52–#65：发布搜索、空回复重试、Secure Cookie、按原话认出被拒绝的候选、学习证据和怀疑，等等。这一轮不比较产品，只检查一件事：**这些改动之后，问答的质量有没有变差。**

## 方法

和第三轮完全相同：

| 项目 | 设置 |
| ---- | ---- |
| 代码 | `origin/main` 的 `f46aba7` |
| 模型 | magpie 网关上的 `auto/deepseek-v4.1-flash`，两个系统相同 |
| 材料、题目 | `material/`、`questions-round-3.json`，每题 3 次 |
| 系统 | `episteme`、`paste-all`（每次把全部材料贴给模型） |
| 运行 | 2026-11-16 08:48–08:56，Node 24.21.0 |

命令（经一个临时启动脚本把网关地址和密钥放进环境变量，不打印密钥）：

```text
node scripts/evaluate.mjs --repeats 3 --max-calls 300 --questions questions-round-3.json --no-journey --systems episteme,paste-all --out round-4.json
```

原始结果：[results/round-4.json](results/round-4.json)。

| 无关问题拒答 | — | 12/12 |
| 材料没有的问题拒答 | — | 12/12，其中 1 次仍附了引用 |

答错的 3 次都是同义改写题 p1，三次都回答“材料里没有足够的依据讲这一点”。这是前几轮已知的问题：关键词检索找不到换了说法的段落。语义检索可以接上，但默认关闭，也没有用真实嵌入模型验证过（网关上没有嵌入模型）。

“材料没有的问题”里，a1 的第 2 次拒答了，但仍附了一条引用。第三轮报告没有单列这一项，所以无法比较。

## 结果：贴全部材料

和 Episteme 一起跑的那一次**没有跑完**：每次请求都贴全部材料，用量大，触发了单次运行的 token 预算（默认 20 万），14 次请求失败。

之后单独重跑了这一组，token 预算调到 60 万（`EPISTEME_MODEL_MAX_TOKENS=600000`），其余设置不变。原始结果：[results/round-4-paste-all.json](results/round-4-paste-all.json)。

| 题型 | 第三轮 | 第四轮（重跑） |
| ---- | ---- | ---- |
| 直接题 | 30/30 | 30/30 |
| 同义改写 | 18/18 | 18/18 |
| 跨文档 | 3/3 | 3/3 |
| 留出题 | 18/18 | 18/18 |
| **合计答对** | **69/69** | **69/69** |
| 无关问题拒答 | — | 12/12 |
| 材料没有的问题拒答 | — | 12/12 |
| 错误 | — | 0 |
| 延迟 p50 / p95 | — | 2.6 s / 3.6 s |
| 用量 | — | 93 次调用，约 24 万 token |

作为对比，Episteme 的 84 次调用约用 15 万 token。小材料上，直接贴全部材料仍然答对最多，用量也更大。

## 结论

- 合并 #52–#65 之后，Episteme 的问答质量和第三轮相同（66/69），没有看到回归。
- 只跑了一个模型、一套小题集、每题 3 次，只能说明“没有明显变差”，不能说明“变好了”。
- 同义改写题 p1 仍然答不出，仍是检索的主要缺口。

## 下一轮依据

- 有嵌入模型可用时，用同一套题比较关键词和语义检索，重点看 p1。
- 贴全部材料的对照，要一开始就调高 token 预算（`EPISTEME_MODEL_MAX_TOKENS`），不然会中途停下。
