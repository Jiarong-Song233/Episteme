# 复用决策记录 0018：关系图的缩放和平移

日期：2026-11-16。新增依赖已经由所有者批准（2026-11-16）。

## 要解决的问题

“我的理解”页的关系图把所有节点限制在一个 320×220 的框里，超出的节点被硬压到框边。节点到几十个时，点和标签叠在一起，看不出结构，也点不准。

## 本仓已有能力

- `d3-force` 3.0.0 负责布局，只跑一次，不做动画。
- 关系图对辅助技术隐藏；下面的列表能用键盘操作，内容和关系图一样。

## 候选

| 方案 | 许可证 | 说明 | 结论 |
| ---- | ---- | ---- | ---- |
| [d3-zoom](https://github.com/d3/d3-zoom) 3.0.0 | ISC | 和 `d3-force` 同一系列；拖动、滚轮、双指捏合、双击都处理好了，还能区分拖动和点击 | 采用 |
| 自己写 viewBox 缩放 | — | 要自己处理触摸、惯性，以及拖动后不要误触点击 | 不做，和“优先成熟实现”的约定不符 |
| 换成整套图库（Cytoscape.js、Sigma.js 等） | MIT | 要重写渲染和样式 | 不必要 |

## 依赖核查

- 直接依赖：`d3-zoom` 3.0.0、`d3-selection` 3.0.1；类型 `@types/d3-zoom` 3.0.9、`@types/d3-selection` 3.0.12，都是精确版本。
- 间接依赖：`d3-dispatch`、`d3-drag`、`d3-interpolate`、`d3-transition`、`d3-timer`、`d3-ease`、`d3-color`，都是 ISC。
- `d3-selection` 固定为 3.0.1，与 `d3-transition` 用的版本相同。如果装两份，`d3-transition` 只会给其中一份加上 `interrupt`，缩放会出错。
- 2026-11-03 发布的几个 d3 新版本，都由 GitHub Actions 通过 OIDC 可信发布，带 SLSA provenance。`d3-selection` 3.0.1 对应 `d3/d3-selection` 仓库的提交 `ec6aa4a` 和标签 `v3.0.1`。`d3-zoom` 3.0.0 是 2021 年由维护者本人发布的。
- 锁文件新增约 120 行，全是 d3 系列，没有安装脚本。
- 加上之后，构建出的页面脚本是 474 KB（gzip 后约 145 KB）。

## 决定

- 布局不再压进框里，打开时按所有节点的范围缩放到能全部看到。只缩小，不放大。
- 拖动可以平移。缩放有三种方式：按住 Ctrl 滚动（触控板捏合也会发出这种事件）、双指捏合、“放大／缩小／看全部”按钮。不按 Ctrl 的滚轮照常滚动页面，不会被关系图截走。
- 最多放大 4 倍，最多缩小到“全部可见”时的一半。
- 布局加一点向中心的拉力（`d3-force` 自带的 `forceX`/`forceY`）。没有关系的节点不然只会互相推开，铺得太散，缩到能全部看到时就小得看不清。

## 验证

- `tests/workbench-web.test.ts`：Edge 打开关系图，所有点都在可见范围内；“放大”会改变视图，“看全部”回到原样；放大后点节点仍能打开那一条。
- 本地运行：40 条已确认的理解。打开时全部可见，比例 0.59；不加中心拉力时是 0.16。普通滚轮滚动了页面，关系图没变；按住 Ctrl 滚动会缩放；拖动会平移，不会误开节点；放大后点节点能打开详情。

## 局限

- 节点到几百个时，“全部可见”的比例会很小，要放大才能读标签。没有聚类或筛选。
- 关系图仍然不支持键盘操作，键盘用户用下面的列表。
- 没有在真实触屏设备上试过双指捏合。
