# 复用决策记录 0007：学习证据作为待确认提议

调查日期：2026-11-13。外部做法来自当日读到的论文和官方文档页面。

## 目标能力

Agent 在学习计划里记下的“答得不对/只对一部分”，现在只留在学习页的场景记录里。本人持有的理解（Core 状态）看不到它，通用的召回和其他场景也看不到。

目标：让这条证据进入理解层，同时守住两条：Agent 不能替本人确认；本人确认之前，理解不变。

## 本仓已有能力

| 来源 | 已有实现 | 用法 |
| ---- | ---- | ---- |
| `session.propose` / `decide` | 状态变更提议、待确认队列、审阅记录 | **直接复用**，不另建队列 |
| ADR 0016 委托 | 委托可以替本人接受提议，但冲突类提议不在其内 | 沿用：怀疑冲突的提议永远等本人 |
| `evidence.ts`（ADR 0019） | 证据按学习目标记；目标只通过 `candidate` 证据连到本人持有的节点 | 用这条已有链接找节点，不新建关联 |
| 学习场景的 `conflict` 维度 | none / suspected / open / resolved，本人可记 | 提议 `suspected`，不提 `open`：是否真有冲突由本人判断 |

## 外部做法

| 项目 | 许可证 | 做法 |
| ---- | ---- | ---- |
| [Bull, Open Learner Models（2016 综述）](https://pmc.ncbi.nlm.nih.gov/articles/PMC6302918/) | 论文 CC-BY | 协商式学习者模型：系统依据证据提出看法，学习者接受或反驳，双方的看法都保留，也可以“先放着”。作者也指出相关研究规模有限 |
| [Moodle Competencies](https://docs.moodle.org/en/Competencies) | GPL-3.0 | 课程活动完成后可以自动把能力标成“已达成”，评分者也可手动评定 |

## 决策

| 项 | 内容 |
| ---- | ---- |
| 复用选项 | 参考后重写：采用协商式学习者模型的“系统提议、本人决定”，落在本仓已有的 `propose`/`decide` 上 |
| 不照搬 Moodle | 自动标记由系统直接决定，违反“Agent 不能替本人确认” |
| 不引入依赖 | 没有可用的库，逻辑只有几十行 |
| 触发 | 只在 Agent 记下的 `attempt` 判为 `partial` 或 `contradicts` 时 |
| 对象 | 这个学习目标下本人已持有（本人或委托接受）的每个节点，各一条 |
| 不重复 | 节点已是 `suspected`/`open`，或已有同维度的待确认提议，就不再提 |
| 委托 | 不替本人决定（ADR 0016 本来就把冲突排除在委托外） |
| 页面 | 待确认列表显示“哪条理解、哪个维度、改成什么”，按钮是“同意，记下来 / 不同意” |

## 成本和风险

- 成本：`host-learning.ts` 一个函数；`/understanding` 多一个 `state` 字段；页面一个分支；一个测试文件。
- 风险：审阅负担。连续答错只会提一次，但一个目标挂着多条理解时会一次提多条。这一点需要真人使用来判断。
- 未覆盖：页面自带练习的答题（`learning.ts`）没有从学习目标到理解节点的链接，这次不处理。
- 验证：`tests/learning-doubt.test.ts`；本机在真实图谱的副本上走一遍。
