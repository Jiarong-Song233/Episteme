# 复用决策记录 0012：计划里写明重点为什么回来了

调查日期：2026-11-13。外部做法来自当日读到的社区文档，未读到 Anki 官方桌面手册的对应段落。

## 目标能力

0009 让本人记下怀疑的理解不再让计划跳过对应重点。但页面上看不出来，这个重点是因为本人记下的怀疑才回到计划里的。本人看到一个“以为已经会了”的重点又出现，会以为是计划出了错。

目标：这样回来的步骤写明原因；怀疑解决后照常跳过，也不再写。

## 本仓已有能力

| 来源 | 已有实现 | 用法 |
| ---- | ---- | ---- |
| `plans.ts` 的 `layOut` 和步骤的 `note` | 跳过的步骤写“你已确认过相关的理解，所以跳过。” | 同一个字段，给因怀疑回来的步骤写原因，步骤仍然是待做 |
| `learning.ts` 的计划生成 | 已经算出持有的理解，并去掉了被怀疑的 | 把被怀疑的单独传给 `layOut` |
| `doubt.ts` 的 `isDoubted` | 本人记下“疑似”或“未解决” | 不改 |
| 学习页的步骤列表 | 只在跳过时显示 `note` | 待做的步骤也显示 |

## 外部做法

| 项目 | 许可证 | 做法 |
| ---- | ---- | ---- |
| Anki（[社区整理的学习说明](https://noobj2.github.io/anki-manual/studying.html)、[AnkiDroid 的牌组列表说明](https://krmanik.github.io/ankidroiddocs/deck-picker.html)） | AGPL-3.0 / GPL-3.0 | 答错回到重新学习的卡片和普通复习卡分开计数，学习者能看出哪些是“忘了又回来的” |

采用的是“回来的东西要和普通的分开标出”这一点。这里写成一句原因，指明是哪一条理解被怀疑了。

## 决策

| 项 | 内容 |
| ---- | ---- |
| 复用选项 | 参考后重写，用已有的 `note` 字段 |
| 不引入依赖 | 不需要 |
| 写哪一条 | 写被怀疑的那条理解的原话，本人能认出是自己记下的哪一条 |
| 改了重点名 | 原因不再成立，编辑时去掉 `note`；跳过步骤的说明同样处理 |
| 已经生成的计划 | 不改 |
| 没有存储改动 | 只在新生成的步骤上多一个已有的可选字段 |

## 成本和风险

- 成本：`plans.ts` 的 `layOut` 多一个可选输入，编辑时改名去掉说明；`learning.ts` 传参；学习页一处显示；两个测试。
- 风险：编辑改名后去掉说明是行为变化，跳过步骤的“已确认过”也会去掉，界面显示“跳过”。
- 验证：`tests/practice-doubt.test.ts` 的“a later plan”；本机在图谱副本上走一遍。
