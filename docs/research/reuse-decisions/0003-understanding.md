# 复用决策记录 0003：G3 理解的提出、演化和再利用

调查日期：2026-11-02。版本来自当日 `npm view`。

## 目标能力

把对话和材料里的话变成待确认的理解，人确认后保留来源；之后可以质疑、修正、标记矛盾、撤回，每一步都留痕；新对话能带出当前持有的说法，并说明它不是材料；页面能浏览关系和时间线，并从理解跳回原话。

## 审计：本仓已有能力

PRD 要求优先整合已有能力，所以先看本仓。

| 能力 | 已有实现 | G3 怎么用 |
| ---- | ---- | ---- |
| 候选和审阅 | `view.distill`、`pendingSuggestions`、`/suggestions/decide` | 所有候选都走这条路，包括人自己的修正。工作台没有写节点的旁路 |
| 原话与推断 | `basis`，引擎核对 stated 的引文确实出自 `learner` 那一方 | 引文落在谁的话里，就算谁说的，不听模型自报 |
| 重复 | 引擎拒绝完全相同的候选（`already_known`、`already_pending`） | 真实运行发现它挡不住措辞略有不同的重复，工作台加了一层词覆盖比较：模型的候选被过滤，人自己提出的只提示相近 |
| 状态与历史 | 只追加的 StateEvent，`/record` 只接受人 | 矛盾和撤回都是状态。撤回不删除节点，可以恢复 |
| 关系 | `evolves_to`、`contradicts`、`supports` 边 | 修正是旧节点 `evolves_to` 新节点，旧节点和它的历史不动 |
| 记录 | `view.records` | 新增 `origin/` 和 `challenge/` 两种记录 |
| 检索 | `view.match` | 图谱的检索器不切中文，所以先用工作台的词覆盖比较标签，再用它补充 |

**新增的只有这些：** 一个 `stance` 维度（放在工作台的 DomainPack 里，Core 不认识它）、`SceneView` 上只读的 `expand`、`apps/workbench/src/understanding.ts` 的路由和读取逻辑。

**有意不做：** 模型不提议状态。说过一件事不等于掌握，所以对话提炼只产生节点和关系，确信程度等只有人能记录。

## 候选项目（关系图）

页面需要一张能点的小图。只用来看结构，节点数量是几十个的量级。

| 项目 | 版本 | 许可证（npm 元数据） | 与本目标的关系 |
| ---- | ---- | ---- | ---- |
| d3-force | 3.0.0 | ISC | 只算布局，渲染自己写；三个小依赖，无安装脚本 |
| cytoscape | 3.34.4 | MIT | 完整的图组件和交互，自带渲染和样式系统 |
| @xyflow/react | 12.12.1 | MIT | 面向可编辑的流程图，节点是可拖动的组件 |
| elkjs | 0.12.1 | EPL-2.0 OR GPL-3.0-or-later | 分层布局很强，但许可证不如前几个简单，体积大 |

## 实现证据

这张图不编辑、不拖动、不缩放，点一下打开那条理解，无障碍路径是图下方的列表。d3-force 算完坐标后由 React 画 SVG，页面的颜色变量直接可用，亮暗两种模式都不用另外配置。

cytoscape 和 @xyflow 的主要能力（交互编辑、缩放平移、样式系统）这里都用不上，还要把样式从页面的变量同步过去。

## 复用选项

1. **d3-force 只算布局，SVG 自己画。**
2. cytoscape：将来图变大、要缩放和筛选时更合适。
3. @xyflow/react：要让人在图上直接编辑时更合适。

## 成本与风险

布局是一次算完的，节点到几百个时图会挤，也没有缩放。到时可以换成 cytoscape，只影响 `Understanding.tsx` 里的 `UnderstandingMap`，数据接口不变。

相近判断用词覆盖（双向都不低于 0.75），否定词数量不同的一律不算相近。它不理解语义：意思相同但用词不同的两条仍会同时出现，不靠否定词表达相反结论的两条（比如“更快”和“更慢”出现在长句里）可能被当成重复，这时模型提炼会漏掉一条候选。所以它只用来过滤模型的候选和提示人；人主动提出的话从不被拦。

## 决策

选 1，新增 `d3-force` 3.0.0 和开发依赖 `@types/d3-force` 3.0.10。其余能力全部复用本仓现有机制，Core 没有改动，application 只多了一个只读方法。
