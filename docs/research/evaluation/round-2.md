# 第二轮评测（2026-11-02）

这一轮验证[第一轮](round-1.md)发现的三个问题修好了没有。它**仍然没有运行任何成熟产品**，G6 的对比项依然没有达成。

```bash
pnpm exec tsc -b
node scripts/evaluate.mjs --repeats 3 --max-calls 300 --questions questions-round-2.json --systems episteme,paste-all --out result.json
```

模型和限额与第一轮相同，原始结果在 [results/round-2.json](results/round-2.json)。题目是 [questions-round-2.json](questions-round-2.json)：第一轮的 21 道题，加上 6 道新的同义改写题和 4 道完全无关的问题。没有再跑 `model-only`。

## 改了什么

| 发现 | 修复 |
| --- | --- |
| 相关性闸门挡下了正确段落 | 门槛从 0.34 降到 0.2，判断“材料是否真的回答了问题”交给模型 |
| 引用只保留前 600 字，答案可能被截掉 | 引用保留模型读到的完整片段 |
| 深学和速通的对话步骤经常收到空回复 | 对话不再以助手消息开头 |

**空回复的根因：** 计划的对话由工作台先开口，发给模型的第一条非系统消息是助手消息。同一条真实提示词重放的结果如下：

| 提示词形式 | 拿到回复 |
| --- | --- |
| 原样（助手开头） | 2/8 |
| 合并连续的助手消息（仍是助手开头） | 3/8 |
| 去掉历史 | 8/8 |
| 前面加一条用户消息，合并助手消息 | 11/12 |
| 前面加一条用户消息，不合并 | 12/12 |

这只在这一个模型上测过。修复方式是加一条用户消息，这也是多数模型接口的常规消息结构。

## 怎么读这些数字

- **修复有效，但主要证明的是第一轮的问题确实存在。** 模型调用从 51 次增加到 84 次，多出的 33 次都算得清：第一轮被闸门挡下的 4 道题现在会问模型（12 次），新的同义改写题 18 次，无关问题里通过闸门的 o4 有 3 次。
- **小材料上 `paste-all` 依然不输。** 它在同义改写题上还多对 3 次，token 多用约 56%。这个差距会随材料变大而扩大，但这一点还没有测过，而且材料大到放不进提示词时，`paste-all` 就不可行了。
- **p1 还是答不出。** 覆盖率最高的是别的片段，正确片段本身不到 0.2，被闸门挡下。关键词检索的这个局限仍然存在，要解决得靠语义检索，那是新依赖，要单独决策。

## 这轮的新局限

- **“新题”不算严格的留出集。** 这些题写在修复之前，但定门槛前我已经看过它们的覆盖率。其中只有 h2、h3 是因为门槛放低才通过的，另外 4 题在旧门槛下也能过。
- **门槛的余量很小。** 两道无关问题的覆盖率是 0.17，门槛是 0.2。这个值来自四份文档和 31 道题，换一批材料可能要重新调。0.2 不是为这组题新造的，它原本就是代码里后续片段的门槛。
- **拒答现在更依赖模型。** o4 和全部无答案题都通过了闸门，是模型自己拒答的。更弱的模型可能不会这样，这一轮只测了一个模型。
- 第一轮第 8 节的其他局限依然成立：作者偏差、规模小、没有真人、不涉及学习效果。
