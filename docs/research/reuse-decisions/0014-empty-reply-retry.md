# 复用决策记录 0014：空回复再问一次

日期：2026-11-13。

## 要解决的问题

真实演示和第二轮评测的重放中，同一条提示词偶尔拿到空回复，页面就报“模型没有返回内容”，要人手动重发。根因（对话以助手消息开头）已在第二轮修掉，但重放里还出现过 1 次空回复。

## 本仓已有能力

- `remoteModel` 用的 `openai` 客户端已经设置了 `maxRetries: 1`：超时、限流、5xx 和连接失败都会由它自动再试一次。
- 空回复不是 HTTP 失败，客户端看到的是成功的响应，所以不会重试。
- `finish_reason: 'length'` 的空回复已经单独报告：思考型模型把输出额度用完了，提示人调参数。

## 参考的做法

| 做法 | 说明 |
| ---- | ---- |
| `openai` 客户端的 `maxRetries` | 只对请求失败重试，不看内容。本仓已经在用 |
| 应用层重试一次 | 和客户端的重试次数保持一致；不引入重试库，因为只有一个调用点、一种条件 |

## 决定

- 只在“内容为空、且不是因为输出额度用完”时，在 `remoteModel` 里再请求一次。被截断的那种再问也会被截断，不重试。
- 只重试一次，第二次还是空的就报错，提示里写明“连续两次”。
- 两次的 token 都计入回复，预算照实扣。调用次数仍按一次计，和客户端自带的重试一致。
- 不改错误码，页面和服务的行为不变。

## 局限

- 重试会让最坏情况的等待时间翻倍。
- 只用模拟服务测过“第一次空、第二次有内容”，没有在真实模型上复现空回复。
