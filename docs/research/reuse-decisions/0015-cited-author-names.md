# 复用决策记录 0015：作者撤回后，引用者仍看得到名字

日期：2026-11-13。

## 要解决的问题

多人模式下，页面上显示的名字来自服务的 `GET /me`，它只列出当前用户自己，以及仍在线的发布的作者。作者撤回全部发布后，名字就不在这张表里了。引用过这份成果的人，在自己的理解里看到的就变成“引用自另一位用户”。可是他们引用时看到过作者的名字。

## 本仓已有能力

- 引用会写下一条状态事件，`source` 为 `publication:<id>`（ADR 0014）。`updates()` 已经用这些事件找出“我引用过的发布”。
- 撤回不删除发布记录，`log.publications.get(id)` 仍然能读到作者 id。

## 参考

没有可复用的外部实现：这是本仓的可见性规则，不是通用能力。规则沿用服务里已有的注释，“在服务上不等于名字公开”。名字只给能读到这个人作品的人看；现在“能读到”也包括“引用时读到过”。

## 决定

- `CognitiveSession.citedAuthors()`：返回这个人引用过的发布的作者，在线的和已撤回的都算。和 `updates()` 共用同一段查找。
- `/me` 的名字表在原来的基础上，加上这些作者。
- 没有引用过的人，看到的和原来一样：作者撤回后不显示名字。
- 不改存储，不改页面。

## 局限

- 只回应（分叉、反驳、支持）而没有引用的人，原作被撤回后，谱系里仍显示“另一位用户”。回应记录不经过 `adopt`，要另找来源。
- 引用后又撤回了自己的引用，名字仍保留：他们读到过。
