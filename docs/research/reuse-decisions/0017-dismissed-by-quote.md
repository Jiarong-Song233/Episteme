# 复用决策记录 0017：被拒绝的候选，换个说法也认得出

日期：2026-11-13。

## 要解决的问题

人点了“不要”的候选，在同一空间里再次提炼时会被跳过，但判断只比较候选的措辞（词覆盖率）。模型换一种说法，比如把“位置编码可有可无”说成“Transformer 不依赖顺序信息也能工作”，就又出现了。人要反复拒绝同一件事，审阅负担变重。

## 本仓已有能力

- 工作台在图谱旁边为每条候选保存来源记录（`origin/<建议 id>`）：标签、空间、对话和轮次。
- 模型提炼时必须给出 `quote`，而且引文必须真的出现在某一轮里，否则丢弃。
- `sameThought`：词覆盖率加否定词计数，否定词数量不同就不算同一个想法。

## 参考的做法

| 做法 | 说明 | 结论 |
| ---- | ---- | ---- |
| 语义相似度（嵌入向量） | 本仓已有可选的语义检索，但默认关闭，也没有用真实模型验证过 | 不做默认依据 |
| 按出处去重 | [W3C Web Annotation](https://www.w3.org/TR/annotation-model/#text-quote-selector) 的 `TextQuoteSelector`（Hypothesis 等标注工具用它锚定）用“原文引文”识别标注落在哪里，而不是看标注写了什么 | 采用这个思路，不引入库 |

模型每次措辞都可能不同，但它引用的原话来自同一轮对话，是稳定的。

## 决定

- 新的来源记录多保存一项 `quote`，即候选引用的原话。旧记录不改写，也没有这一项，只能照旧按措辞比较。
- 模型提炼出的候选，如果和某条被拒绝的候选来自**同一轮**，引文按 `sameThought` 算作相同，而且标签的否定词数量相同，就不再提出。
- 否定词数量不同的，仍当作相反观点照常提出（原有测试保持不变）。
- 人自己提出的、人要求提炼的整句，不受影响。
- 页面上看到的来源信息不变，`quote` 和标签、空间一样不发给页面。

## 局限

- 只在同一轮里认得出。同一个意思在另一轮里又说了一遍，还是会提出。
- 一句话里同时说了两件事，拒绝了其中一件，模型如果对另一件引用了几乎同一段原话，也会被跳过。
- 这一项之前被拒绝的候选，没有引文，仍只按措辞比较。
