# 复用决策记录 0010：答题前就能关联理解

调查日期：2026-11-13。外部做法沿用 0008 当日读到的产品文档，这次没有再查新的来源。

## 目标能力

0008 让本人把一条理解关联到学习目标，之后页面上答错会问到这条理解。但页面计划的目标要答过一次才出现，所以第一次答错时一定还没关联，提不出怀疑；0008 的风险一节记了这一点。

目标：页面计划一生成，它要练习的重点就列为目标，本人可以在答题之前先关联。

## 本仓已有能力

| 来源 | 已有实现 | 用法 |
| ---- | ---- | ---- |
| `evidence.ts` 的 `objectivesOf` | 按记录的目标和已答的题列出目标 | 加一个可选项，再加上页面计划要练习的重点 |
| `objectiveIdOf` | 按空间和重点名算目标 id | 计划步骤和答题用同一个 id，答题后自然合到同一个目标 |
| 学习库的 `interaction: 'practice'` | 标出会出题的活动 | 只取这类步骤，概览、讲解、总结用的是主题，不算目标 |
| 概览页 `evidenceWords` | 0 次时写“还没有答题记录” | 不改 |
| `POST /objectives/link` | 本人关联理解 | 目标查找用同一个可选项；答题前关联时，记在最新一个计划练习这个重点的计划下 |

## 外部做法

| 项目 | 许可证 | 做法 |
| ---- | ---- | ---- |
| [Canvas：把学习成果对齐到题库](https://community.canvaslms.com/docs/DOC-1906) | AGPL-3.0 | 学习结果先建好、先和题库对齐，学生作答之后才有掌握度 |
| [Moodle Competencies](https://docs.moodle.org/en/Competencies) | GPL-3.0 | 能力先挂到课程和活动上，再收集证据 |

两者都是“目标先于作答存在”，对齐在作答之前完成。这里采用同样的顺序：计划的重点就是目标，关联可以先做，证据后来。不同的是：这里不另建目标实体，目标就是计划里要练习的重点，id 和答题时一样算。

## 决策

| 项 | 内容 |
| ---- | ---- |
| 复用选项 | 参考后重写，改动在已有的目标列表上 |
| 不引入依赖 | 不需要 |
| 只取练习步骤 | 用学习库判断，不按“重点名是否等于主题”猜 |
| 默认不开 | 只有概览和关联两处带上这个选项；Agent 的进度、提议怀疑仍按原来的列法，行为不变 |
| 会话列表 | 页面计划只列出有事件的目标，只计划未答题的计划不出现，和原来一致 |
| 没有存储改动 | 不写新记录，不改旧记录 |

## 成本和风险

- 成本：`evidence.ts` 两个小函数和一个可选项；`routes.ts` 三处传参；三个测试。
- 风险：计划被编辑后改了重点名，原来的目标仍按旧名留在列表里（目标 id 由名字算出），已关联的证据不丢。
- 验证：`tests/practice-doubt.test.ts` 的“before the first answer”；本机在图谱副本上走一遍。
