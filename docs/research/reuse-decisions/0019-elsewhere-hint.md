# 复用决策记录 0019：在回答旁指出别的空间里相关的理解

日期：2026-11-16。

## 要解决的问题

人在“机器学习”空间确认过“位置编码告诉模型词的顺序”，之后在“另一门课”空间问“位置编码有什么用”，对话完全不提这一条。空间是边界，这是对的：一个空间的回答只依据这个空间的材料和理解。但人自己已经想明白的东西，换个空间就像没发生过，复用断在了空间之间。

## 本仓已有能力

- `recalledFor`：同一空间里与问题相关的已确认理解，用词覆盖率判断（中文不分词也能用），放进回答旁的“你之前确认过”，同时作为“不是材料”的提示交给模型。
- `heldNodes`、`stillHeld`：一个空间里此人仍然持有的理解（已修正或撤回的不算）。
- 空间是场景记录 `space/<id>`，带名称和是否归档。

## 参考的做法

| 做法 | 说明 | 结论 |
| ---- | ---- | ---- |
| 笔记工具的“未链接的提及” | Obsidian、Logseq 在页面下方列出别处提到同一名称、但没有链接过来的地方，只列出，不自动合并 | 采用这种“只指出、由人决定”的方式 |
| 把别的空间的理解一起交给模型 | 回答会用到另一个空间的内容，空间就不再是边界 | 不做 |

## 决定

- 回答生成之后，用同样的词覆盖率门槛（0.34）在此人**其他未归档的空间**里找仍然持有的理解，最多两条，分数高的在前。
- 结果作为 `elsewhere` 和回答一起保存，重新打开对话时仍然显示。页面写“你在别的空间也确认过相关的理解（这次回答没有用到）”，每条注明所在空间，点开就切到那个空间的这一条。
- 模型看不到这些内容：只在模型调用之后才计算。
- 归档的空间不指出：人已经把它放到一边了。
- 不改存储，没有新依赖。

## 验证

- `tests/workbench-understanding.test.ts`：
  - 在 A 空间确认一条，在 B 空间问相关问题时，回答带上指向 A 的这一条，发给模型的消息里没有这句话；
  - 重新打开对话仍然显示；
  - 无关问题不指出；
  - A 空间归档后不再指出。
- 本地运行：页面上两个空间，在“另一门课”提问，回答下方出现“位置编码告诉模型词的顺序（在‘机器学习’）”；点开后切到“机器学习”空间的这一条，控制台没有错误。

## 局限

- 相关性只是词覆盖率，同义改写认不出。
- 只看此人自己的理解，不看别人发布的成果。
- 每次提问都会遍历所有空间的理解，空间和理解很多时要再看性能。
