# 复用决策记录 0013：发布搜索按词全部命中

日期：2026-11-13。

## 要解决的问题

浏览发布时，搜索框只把整句当成一个子串去匹配根节点的标题。搜“重放 checksum”找不到一条根是“崩溃恢复要按顺序重放日志”、成员里有“Checksum mismatch”的发布；写在说明里的词也搜不到；全角字母和大小写不同也会漏掉。

## 本仓已有能力

- `browsePublications({q, scope})`（`packages/application/src/session.ts`）已经拿到每条发布的根节点和成员 id，图谱节点在内存里。
- 服务的 `GET /publications?q=` 和页面搜索框都走这一个函数，不需要改路由和页面。

## 参考的做法

| 做法 | 多个词怎么组合 | 和这里的关系 |
| ---- | ---- | ---- |
| [SQLite FTS5](https://www.sqlite.org/fts5.html) | 空格分开的词是隐式 AND | 语义一致。但默认分词器 `unicode61` 不切中文，中文整段算一个词，搜“重放”找不到“按顺序重放日志” |
| [MiniSearch](https://lucaong.github.io/minisearch/) | 默认 OR，`combineWith: 'AND'` 可改 | 要建索引、要新依赖；发布数量小，不值得 |

结论：采用“空格分词、每个词都要出现”的 AND 语义；每个词仍按子串匹配，这样中文不需要分词也能搜到。匹配前对查询和文本都做 NFKC 归一和小写，全角字母、大小写视为相同。

## 决定

- 不引入依赖，不建索引，不改存储。
- 匹配范围：根节点标题、成员标题、发布说明。不含对话摘要原文（发布只带摘要，搜索摘要可以以后再定）。
- 只有空白的查询等于不过滤，和原来一样。

## 局限

- 不按相关度排序，结果顺序和原来一样，新发布在前。
- 不做同义词、拼音或语义匹配；“日志”搜不到只写了“log”的发布。
- 每次搜索都遍历全部在线发布和成员，发布到几千条时要再看性能。
