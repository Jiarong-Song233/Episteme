# 复用决策记录 0002：G2 学习计划与工作流

调查日期：2026-11-02。版本来自当日 `npm view`。

## 目标能力

用户给主题、时间和模式，得到可编辑的计划；计划按步骤走，可暂停、恢复、改动，模型失败后可重试。速通和深入是两条声明式流程，用户可以加自己的流程，不改代码。

## 实现证据

本仓现有能力已覆盖流程需要的东西：`view.records` 保存步骤和答题，`view.threads` 保存对话，scene 路由带写入身份和拒绝语义。流程是线性的，由人一步一步推进，整个状态是一条不超过 64 KB 的记录。

LangGraph 和 Mastra 解决的主要问题（分支图、并行节点、长时间运行的 Agent 循环、框架级 checkpoint）这里都没有。XState 最接近，但这条流程的转移只有“下一步、跳过、重试、暂停”，写成状态机不会比现有函数更短。

## 复用选项

1. 引入 LangGraph：能力多，但要把两个 peer 依赖和图模型放进工作台，而状态还得存回本仓记录。
2. 引入 XState：干净，但多一层抽象换不来新能力。
3. **自己写一个很小的线性步骤器，声明式配置放在 `blocks.ts`：连声明带路由约 900 行，依赖为零。**

## 成本与风险

自写的风险是将来要分支、并行或自动循环时不够用。到时可以把 `learning.ts` 的 `act` 换成适配器后面的框架，计划记录和接口不必变。

## 决策

选 3，不新增依赖。工作流只留在 `apps/workbench`，Core 和 application 没有改动。其他两个框架记录在这里，真需要分支或 Agent 循环时再比较。
