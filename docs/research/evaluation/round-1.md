# 第一轮评测（2026-11-02）

**结论先说**：这一轮只比了 Episteme 和两个同模型基线，**没有运行任何成熟产品**，所以 G6“与成熟产品或开源项目实际对比”这一项还没有达成。

在这组小材料上，“把全部材料贴进提示词”在问答上不比 Episteme 差，同义改写题还明显更好（18/18 对 6/18）。Episteme 的落差主要来自它自己的相关性闸门，第 5 节有依据。

## 1. 怎么复现

```bash
pnpm exec tsc -b
node scripts/evaluate.mjs --repeats 3 --max-calls 300 --out result.json
```

需要设置 `EPISTEME_MODEL_BASE_URL`、`EPISTEME_MODEL_NAME` 和 `EPISTEME_MODEL_API_KEY`。没有配置模型时脚本拒绝运行，除非显式传 `--simulated`，这时报告会标明是模拟结果。只看检索、不调用模型时用 `--retrieval-only`。

| 项目 | 取值 |
| --- | --- |
| 代码 | `feat/evaluation`，基于 706a9cc |
| 模型 | 三个系统相同：magpie 网关上的 `auto/deepseek-v4.1-flash`。`auto/` 路由可能换上游，不同日期的结果不一定可比 |
| 限额 | 每个系统最多 300 次调用、100 万 token，单次超时 60 秒。实际远低于限额，见第 3 节 |
| 材料 | [material/](material/) 下四份虚构文档，共约 3900 字，其中一份面包配方是干扰项 |
| 题目 | [questions.json](questions.json)：10 道直接题、6 道同义改写题、1 道跨文档题、4 道材料没有答案的题 |
| 重复 | 每题 3 次，共 63 次。同一题的 3 次不是独立样本 |
| 原始结果 | [results/round-1.json](results/round-1.json)，含每次回答的原文，可以重新判分 |

材料是虚构的，这样模型无法靠已有知识作答。`model-only` 基线答对 0 题，说明这一点成立。

## 2. 比了什么

| 系统 | 做法 | 回答什么问题 |
| --- | --- | --- |
| `episteme` | 完整产品，走它自己的 HTTP 接口 | 被测对象 |
| `model-only` | 同一模型，不给材料 | 模型是否靠先验知识就能答 |
| `paste-all` | 同一模型，把全部材料贴进提示词，没有检索 | 一个人直接用聊天工具能做到什么程度 |

`paste-all` 不是成熟产品，只是一条下限。它只在材料放得进一次提示词时才可行，这组材料正好放得下。

**判分规则对所有系统相同**：

- 答对：回答文本匹配正则形式的标准答案。
- 引用到位：某条引用来自正确文件，并且引用展示的文字里确实有答案。`paste-all` 的引用是模型自己说的，所以只有逐字出现在文件里才算数。
- 拒答：回答文本里出现“没有”“无法”“不知道”等说法。这个规则很宽松，所以原始回答都保留了。

## 3. 问答结果

单元格是“次数/总数”。

| 指标 | episteme | paste-all | model-only |
| --- | --- | --- | --- |
| 直接题答对 | 30/30 | 30/30 | 0/30 |
| 直接题答对且引用到位 | 27/30 | 29/30 | 0/30 |
| 同义改写题答对 | **6/18** | 18/18 | 0/18 |
| 同义改写题误拒答 | **12/18** | 0/18 | 17/18 |
| 跨文档题答对且引用到位 | 3/3 | 3/3 | 0/3 |
| 无答案题拒答 | 12/12 | 12/12 | 12/12 |
| 引用落在正确文件的比例 | 0.936 | 0.952 | 无引用 |
| 引用文字长度中位数 | **600 字** | 30 字 | 无引用 |
| 延迟 p50 / p95（毫秒） | 2341 / 3839 | 2428 / 3225 | 2865 / 4249 |
| 模型调用 / token | 51 / 10.1 万 | 63 / 16.1 万 | 63 / 1.3 万 |
| 出错次数 | 0 | 0 | 0 |

`model-only` 的 12/12 拒答没有意义，它对所有题目都说不知道。

## 4. 任务走查

下面是 PRD 列的任务，只在 Episteme 上走，目前没有可比对象。任务“完成”的判据是它该留下的状态确实能读回来。

| 任务 | 完成 | 接口请求 | 模型调用 | 耗时 |
| --- | --- | --- | --- | --- |
| 上传（含重复文件识别） | 是 | 7 | 0 | 0.05 秒 |
| 引用问答 | 是 | 1 | 1 | 2.6 秒 |
| 计划 | 是 | 2 | 1 | 6.6 秒 |
| 速通 | 是 | 8 | 5 | 23.5 秒 |
| 深学与练习 | 是，**但有一步被跳过** | 12 | 7 | 39 秒 |
| 存取理解 | 是 | 7 | 0 | 0.06 秒 |
| 修正 | 是 | 5 | 0 | 0.03 秒 |
| 跨会话复用（重启服务后） | 是 | 5 | 1 | 3.8 秒 |
| 跨身份引用 | 是 | 10 | 0 | 0.09 秒 |

- **这张表说明流程能走通，不说明好用。** 步骤是脚本发的请求，不是真人操作，也没有测审阅负担和学习效果。
- **深学的“举例和反例”这一步被跳过了。** 模型连续两次返回空内容（`empty_reply`），脚本按一个人的做法重试一次后跳过。上一次试跑时，也有一步对话遇到空回复后被跳过。问答的 177 次模型调用里没有出现过空回复，所以问题可能只出在对话步骤，原因还没查。
- **练习题质量：** 人工读了最后一次运行生成的 3 道选择题，都能在材料里找到依据，干扰项也合理。样本太少，不能当成结论。
- **复用只在同一空间内发生。** 同样的问题换到另一个空间问，不会带回之前的理解。这是 G3 的设计（`tests/workbench-understanding.test.ts` 有断言），但有多个主题的用户可能会感到意外。

## 5. 问题出在哪

`--retrieval-only` 不调用模型，直接检查检索的每一层：

| 题目 | 正确段落的排名 | 最高覆盖率 | 过闸门（≥0.34） |
| --- | --- | --- | --- |
| p1 同义改写 | 2 | 0.27 | 否 |
| p3 同义改写 | 1 | 0.22 | 否 |
| p4 同义改写 | 2 | 0.25 | 否 |
| p5 同义改写 | 2 | 0.29 | 否 |
| p2、p6 同义改写 | 2 | 0.50、0.73 | 是 |
| a1–a4 无答案 | 无 | 0.83、0.56、0.67、0.40 | **全部通过** |

1. **相关性闸门是同义改写题失败的唯一原因。** 12 次误拒答全部来自被挡下的这 4 道题，正确段落其实已经排在前两名。不过语料一共才十来个片段，排名靠前本来就容易，语料变大后不能指望这个结果。
2. **闸门没有挡住任何无答案题。** 它们全部通过了闸门，拒答都是模型自己标注的。在这组题上，闸门只有代价，没有测到收益。但它原本要防的是“完全无关的问题”，而这组题没有这一类，所以还不能下结论说它没用。
3. **引用文字被截断。** d5 的 3 次回答都正确，引用的文件也对，但引用只保留片段的前 600 字，答案在后面，读者看不到依据。这是 `MAX_QUOTE` 造成的真实缺陷，“证据是否支持”的检查用的也是这段截断后的文字。
4. **引用太长，不好核对。** 中位数 600 字，读者要自己在里面找答案所在的句子。回答的 `evidence` 字段会挑出最接近的句子，但这一轮没有评测它。

## 8. 这轮评测的局限

- **作者偏差：** 材料、题目和判分规则都由写 Episteme 的同一个智能体编写。同义改写题是有意避开原词的，但也可能在其他方面偏向某一方。
- **规模太小：** 四份文档、21 道题。这种规模最有利于 `paste-all`，也让检索显得比实际更容易。结果不能外推到大材料。
- **判分粗糙：** 正则只能判断关键事实是否出现，不判断解释质量。回答里同时出现正确事实和错误说法时，也会算对。
- **没有真人：** 没有测学习效果，也没有测审阅负担，所以**不对学习效果做任何判断**。
- **只有一个模型：** 拒答能力很可能因模型而异，闸门在弱模型上可能更有价值。
- **语料全是中文 Markdown：** PDF 和其他格式没有覆盖。

## 9. 下一轮的决策依据

| 发现 | 决定 |
| --- | --- |
| 闸门误伤同义改写题，且没有挡住无答案题 | 加入完全无关的问题和新的同义改写题后重测，再决定闸门放宽还是移除 |
| 引用被截断，答案不可见 | 修复：不再截断 |
| 引用太长 | 评测 `evidence` 字段选出的句子是否命中答案 |
| 对话步骤反复出现空回复 | 查明原因 |
| 小材料上 `paste-all` 不输 | Episteme 不能以“问答更好”为卖点。值得保留的理由要看理解的保存、修正和跨身份复用，而这一点要等真人使用后才能评估 |
| 没有和成熟产品对比 | 需要用户授权后，运行一个具体项目 |

**值得质疑的功能：** 相关性闸门目前只测到了代价。其余功能这一轮没有足够数据支持保留或去掉，不做判断。
