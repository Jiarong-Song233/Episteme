# 复用决策记录 0008：页面练习连到本人的理解

调查日期：2026-11-13。外部做法来自当日读到的官方文档和社区文档页面。

## 目标能力

0007 只覆盖 Agent 记下的答题。页面自带练习（`learning.ts`）的答题也按学习目标记成证据，但学习目标和本人持有的理解之间没有任何链接，所以页面上答错也问不到本人的理解。

目标：让本人自己说明“这个学习目标说的是我的哪条理解”。说明之后，页面上答错和 Agent 记下的答错一样，提出一条待确认的怀疑。

## 本仓已有能力

| 来源 | 已有实现 | 用法 |
| ---- | ---- | ---- |
| `evidence.ts`（ADR 0019） | 学习目标只通过 `candidate` 证据连到节点；页面答题经 `fromPractice` 读成证据 | **直接复用**：本人关联时写一条 `candidate` 证据，`recordedBy: 'person'`，不新建关联表 |
| `doubt.ts`（0007 的 `proposeDoubt`） | 答错时按目标找到节点并提出待确认的 `conflict: suspected` | 从 `host-learning.ts` 挪成共用模块，页面答题也调用 |
| 场景路由权限 | 不在 `route-access.ts` 里的路由只收本人的凭据 | 新路由 `/objectives/link` 不加进去；`scene-route-access` 测试会逐个检查 |
| 节点的 `fromSuggestion` | 节点记着它从哪条候选来 | 证据只能指向候选，所以没有来源、引用来的、已撤回的节点不能关联 |

## 外部做法

| 项目 | 许可证 | 做法 |
| ---- | ---- | ---- |
| [Canvas：把学习成果对齐到题库](https://community.canvaslms.com/docs/DOC-1906) | AGPL-3.0 | 教师把一个学习成果对齐到整个题库；学生答题的正确率自动折算成掌握度，进入 Learning Mastery Gradebook |
| [Moodle Competencies](https://docs.moodle.org/en/Competencies) | GPL-3.0 | 能力挂到活动（包括测验）上；活动完成时可自动附上证据、送审或直接标成达成 |

两者的共同点是“先由人说明题目考的是哪项能力，答题结果才算到这项能力上”，这一点采用。不同的是：两者由教师做对齐，结果直接算成掌握度。

## 决策

| 项 | 内容 |
| ---- | ---- |
| 复用选项 | 参考后重写：采用“先对齐，答题才算数”，对齐落在已有的 `candidate` 证据上 |
| 谁对齐 | 本人。个人版没有教师；Agent 也不能替本人说“这条理解就是这个目标” |
| 不照搬自动折算 | Canvas 和 Moodle 都把答题结果直接算成掌握度或达成；这里只提出待确认的怀疑，确认前理解不变 |
| 不引入依赖 | 只是一条路由和一个下拉框 |
| 粒度 | 一个学习目标对一条理解，一次一条；同一条重复关联返回 `linked: false`，不重复记 |
| 页面 | 概览“现在的情况”里每个目标下有“关联我的一条理解”，只列可关联的理解 |

## 成本和风险

- 成本：一条路由；`learning.ts` 答题后多两行；`doubt.ts` 从 `host-learning.ts` 挪出；页面一个小控件；一个测试文件。
- 风险：页面目标只在答过一次之后才出现，所以第一次答题前无法关联。要不要提前列出计划里的目标，需要真人使用来判断。
- 风险：关联错了目前不能取消。关联本身不改理解，影响只是之后答错时多问一次，本人可以点“不同意”。
- 验证：`tests/practice-doubt.test.ts`；本机在图谱副本上走一遍。
